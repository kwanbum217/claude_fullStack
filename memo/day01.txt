1. 웹 서비스가 만들어지는 순서
: 기획 -> 프론트엔드 -> 백엔드 -> DB -> 배포 순서로 진행된다.
	 
	[웹 서비스 프로세스를 식당으로 비유]
	- 기획 : 무슨 식장을 오픈할지 정하기(무엇을/누가/어떤 화면)
	- 프론트엔드 : 손님들이 보는 '홀' (웹 화면, 버튼, 글자, 글씨 색) -> HTML/CSS/JS
	- 백엔드 : 손님들이 볼 수 없는 '주방'(로그인 확인, 데이터 저장, 계산)
	- DB : 창고 또는 냉장고에 있는 식자재 (회원 정보, 게시글, 주문 내역 데이터 보관)
	- 배포 : 식당 개업 (인터넷에 업로드하여 누구나 접속하고 활용하게 한다.)

- 1개월차 (클로드 웹 개발1)
: 개발 환경 설정 -> HTML/CSS/JS 기초 -> Git/Docker -> 서버 기초
: 재료 준비 + 홀 (화면) 만드는 법을 익힌다.
- 2개월차 (클로드 웹 개발2)
: 백엔드 심화(Prisma/ORM) -> 프론트엔드, 백엔드 연동 -> 디버깅 -> 배포 -> 최종 프로젝트

2. 바이브 코딩(Vibe Coding)
: 기존의 개발 환경은 사람이 코드를 한줄 씩 다 타이핑하였고, 오류도 사람이 직접 수정하였다.
: 바이브 코딩은 사람이 원하는 걸 정확히 설명한다면, AI가 코드를 생성하고 사람이 검토 및 수정을 요청하여
AI가 다시 작업을 반복하게끔 하는 행위를 바이브 코딩이라고 한다.
	(사람이 AI에게 요청 -> AI가 코드 생성 -> 검토 /수정 요청)
: AI가 다 해준다(X) -> AI와 정확하게 대화하는 능력(O)
: AI는 사람의 머리속을 읽지 못하기 때문에 정확히 명령을 내려야한다. 그래서 이 과정은 코딩 문법 + 프롬프트 명령법을 함께 학습할 수 있다.

3. Claude, ChatGPT, Cursor 차이
- Claude(Anthropic) : 대화형 AI 이며, 기획, 설명, 코드 초안, 문서 정리에 강하다.
- ChatGPT(OpenAI) : Claude와 비슷한 대화형 AI , 가장 널리 쓰임
- Cursor : AI 내장 코드 편집기 (VSCode 기반), 프로젝트 전체를 보면서 그 자리에서 코드 작성 및 수정

4. 개발자 사고방식 = 컴퓨터 처럼 생각하기, 문제를 쪼개기
: 큰 개념의 문제는 그대로 표현할 수 없다. 따라서 작은 조각으로 쪼갠다.
: AI에게 명령 시 하나의 단위를 여러 조각으로 세분화하여 자세하게 설명을 해야한다.

	ex) '쇼핑몰 만들어줘'(구체적이지 않고, 개념이 너무 방대하다)
	-> 메인화면 설계 및 기능들 설명 -> 장바구니 -> 결제 -> 주문내역(조각으로 쪼갠다.)

	[나쁜 질문]
	웹 사이트 만들어줘

	[좋은 질문]
	학원 공지사항 웹페이지 만들껀데, 제목/작성일/내용 보이는 목록화면 하나만 HTML로 만들어줘

5. RCF 공식
(1) R (Role, 역할)
: '너는 10년차 웹 개발자야'와 같이 AI에게 상황에 맞는 역할을 부여한다.
(2) C (Context, 맥락)
: '내가 아직 웹 페이지 만드는게 서투르다. 학원 공지사항 웹페이지 만들껀데, 제목/작성일/내용 보이는 목록화면 하나만 HTML로 만들어줘'와 같이 내 상황을 설명하고, 요구사항을 작성한다.
(3) F (Format, 형식)
: 위의 역할과 맥락을 부여하고, 결과를 얻을 시 원하는 형태를 요구한다
