1. DOM 조작(DOM Manipulation)
		:DOM(Document Object Model)이란, HTML문서를 JavaScript가 다를 수 있는 객체 구조로 표현한 것이며, DOM 조작이란 이 구조를 JavaScript로 읽고 바꾸는 작업을 의미한다.
		:document.querySelector()로 요소를 선택하여 객체를 만들고, 객체.textContent, 객체.innerHTML, 객체.style 등으로 내용이나 스타일을 변경한다.
		:DOM은 웹페이지이긔 설계도이자 실제 건물로 비유할 수 있다. querySelector는. '몇층 몇호 '를 찾는 것과 같고, textContent나 stlye을 바꾸는 것은 그 방의 벽지나 가구를 바꾸는 것과 같다.

	[DOM 조작 실습 프롬프트]
	버튼을 클릭하면 화면의 제목(h1)텍스트와 글자 색깔이 바뀌는 index.html, script.js 파일을 만들어라. querySelector로 요소를 선택하고 textContent와 style.color를 변경하는 코드로 작성해줘. 해당 파일들은 day06폴더에 저장하라.

2.fetch
		:fetch란 JavaScript에서 서버에 데이터를 요청하고 응답을 받아오는 내장함수이다.
		:fetch(url)은 Promise(비동기 처리 객체)를 반환하며, .then()으로 응답이 오면 처리할 작업을 이어서 작성한다.  오늘은 개념 설명 위주로 다루고, 상세 실습(POST, async/await)은 추후 진행한다.
		:fetch는 편지를 보내고 답장을 기다리는 것과 같다. 편지를 보내는(요청) 순간 바로 답장이 오지 않으므로, '답장이 오면 이렇게 하겠다'고 미리 적어두는 것이 .then()이다. 이렇게 기다리는 동안 다른 일을 할 수 있는 것이 비동기(async)처리이다.

3. 브라우저 <-> 서버 <-> DB흐름
		:웹 사이트가 동작할 때 데이터가 오가는 전체 경로를 말한다.
		:브라우저(클라이언트)가 요청을 보내면 서버가 받아서 처리하고, 필요하면 DB(데이터베이스)에서 데이터를 조회하거나 저장한 뒤, 다시 서버를 거쳐 브라우저로 결과를 돌려준다.
		:지금까지는 JS로 화면(브라우저)안에서만 동작을 만들었다. 하지만 로그인, 게시글 저장, 회원 목록조회처럼 '데이터를 저장하고 불러오는'기능은 브라우저 혼자 할 수 없다. 따라서 이때 서버와 DB가 필요하다.
		-브라우저(클라이언트): 사용자가 보는 화면. 요청을 보내고 응답을 받아서 화면에 표시한다.
		-서버
		:브라우저(클라이언트)로부터 요청을 받아서 처리하는 중간 관리자를 의미한다.
		:DB에 데이터를 넣거나 꺼내는 역할을 한다.
		-DB(데이터베이스) : 실제 데이터가 저장되어 있는 창고.

		ex)
		-손님(브라우저):'돈까스 하나 주세요' -> 요청
		-웨이터(서버):주문을 받아 주방에 전달하고, 완성된 음식을 다시 손님에게 전달한다.
		-주방:실제 재료(데이터)가 보관되어 있고, 요리(데이터 조회/수정/저장)를 하는 곳

		-손님(브라우저)은 주방에 직접 들어가지 않는다. 반드시 웨이터(서버)를 거쳐서 완성된 음식(원하는 데이터)을 받는다.

4. HTTP
		:HTTP(Hyper Text Transfer Protocol)란 브라우저와 서버가 데이터를 주고 받을 때 지키기로 약속한 통신 규약을 의미한다.
		:브라우저가 서버에 보내는 것을 요청(Request), 서버가 브라우저에 돌려 주는것을 응답(Response)이라고 한다.
		:요청에는 Method(방식)가 있는데, 대표적으로 GET(데이터 조회), POST(데이터 생성/전송)가 있다.
		:응답에는 상태 코드(Status Code)가 붙어서 결과가 성공인지 실패인지 알려준다.
			- 상태코드 200 :성공
			- 상태코드 404 :찾을 수 없음
			- 상태코드 500 :서버 오류

		ex)HTTP는 관공서에 서류를 요청하는 것과 같다.'등본을 열람만 하고 싶다(GET)'와 '새 서류를 접수하고 싶다(POST)'는 신청 방식 자체가 다르다. 그리고 접수증(상태코드)을 보면 '처리완료(200)'인지 '서류없음(404)'인지 바로 알 수 있다. 관공서 직원이 서류를 발급하는 방법을 모르는 경우(500)

5. API
		:API(Application Programming Interface)란 서버가 '이런 형식으로 요청하면 이런 데이터를 주겠다'라고 미리 정해놓은 약속된 창구다.
		:프론트엔드(브라우저의 JS코드)는 서버 내부 코드가 어떻게 작성되어 있는지 몰라도, API가 정해놓은 주소(endpoint)와 형식대로 요청만 보내면 원하는 데이터를 받을 수 있다.
		
		ex)API는 식당 메뉴판과 같다. 손님(브라우조)은 주방(서버 - DB)에서 어떻게 요리하는지 몰라도, 메뉴판(API 문서)에 적힌 이름 그래도 주문(요청)하면 정해진 음식(데이터)이 나온다. 만약 메뉴판이 없는 요리를 주문할 수 없듯, API문서에 없는 주소로는 요청해도 원하는 데이터를 받을 수 없다.
